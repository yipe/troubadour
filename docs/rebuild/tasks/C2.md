## Backend
1. **Start options.** `StartIn` (every source kind) accepts `title` (≤120, stripped, default `""`), `present_player_ids` (≤32 seated ids; unknown ids → 400), `record_audio` (bool, default `config.RECORD_AUDIO`) and `cleanup` (bool, default `config.CLEANUP`). They're stored on `LiveSession`; `record_audio` and `cleanup` replace the config reads for that session only. Live `Session` JSON adds `title` and `present_player_ids`.
2. **Who's here helps matching.** When `present_player_ids` is non-empty, voices belonging to players not present are left out of speaker matching for this session (unnamed voices and new voices behave as before). Test with the fake embedder: an absent player's voice is never chosen.
3. **meta.json** (written where the engine writes it today) gains `title`, `present_player_ids`, `reviewed_at: null`, `talk`.
4. **`talk`**: seconds per player id (`t_end - t_start` summed per line; lines without a player under `"voice:<voice_id>"`). Computed when the record is saved. For older sessions it's computed from `transcript.json` when listed, cached in memory keyed by `(id, transcript mtime)`, and **not** written back.
5. **`lore/pages.py`**:
   - `session_numbers(sessions: list[dict]) -> dict[str, int]`: 1-based, oldest first, skipping sessions merged into another. The same rule as the client's `sessionNumbers` (S2); both have the same test cases.
   - `session_page(vault_dir, rel_path) -> {"title": str | None, "summary": str | None}`: reads the write-up page. The title is the page's title (as the write-up writes it); the summary is the first paragraph of the wrap-up section, stripped of Markdown links, at most 600 chars. A missing or unreadable page gives `None`s.
6. **SavedSession** (list and single summaries) adds `title` (the write-up title if written up, else the working title, else null), `summary`, `present_player_ids` (null for old sessions), `reviewed_at`, `talk`, `n` (from `session_numbers`).
7. `POST /api/sessions/{id}/reviewed {reviewed: bool}` sets or clears `reviewed_at` (epoch s) in meta.json, as a patch (read-modify-write under the engine lock, like other meta writes). 404 for an unknown id.
8. `spike/seed/sessions.py`: titles, present players, `talk`, and `reviewed_at` for S1–S10 (S11 written up but not reviewed, S12 needs review, S7 not written up).

## Web (`@troubadour/api/session`, `@troubadour/api/sessions`)
Types and endpoints for all of the above; `useStartSession` takes the new options; `useMarkReviewed(id)` invalidates `keys.sessions()`.

## Contract rule
Every endpoint you add or change declares a pydantic `response_model` (payload shapes as classes in the router, or in `server/models.py` when two routers share one). In `@troubadour/api`, its types are `Schemas["<Model>"]` from `../generated` (the B6 recipe), not hand copies. WebSocket payloads reuse the same models. Run `pnpm -C web/packages/api gen` after changing a model.

## Tests (`backend/tests/test_session_meta.py`)
Start with options → `Session` JSON shows them; `record_audio=False` writes no `audio.wav` for a mic session (fake source, as in `test_recording.py`); an unknown present id → 400; `talk` sums per player; `session_page` on a fixture page; `session_numbers` passes every case in `shared/test-vectors/session-numbers.json`; reviewed set and clear; an old meta without the new keys lists fine with nulls.
