## Build
- `query/client.ts`: `makeQueryClient()` with defaults `staleTime: 30_000`, `retry: 1`, `refetchOnWindowFocus: false`. Mutation errors don't throw globally; pages show them.
- `query/keys.ts`: one `keys` object, e.g. `keys.campaign()`, `keys.entity(name)`, `keys.sessions()`, `keys.session(id)`, `keys.record(id)`, `keys.quality(id)`, `keys.cloud()`, `keys.cloudAccount()`, `keys.cloudVaults()`, `keys.llm()`, `keys.models()`, `keys.mics()`, `keys.sources()`, `keys.clones()`, `keys.suggestions()`, `keys.classes()` (C1), plus keys for the C-domains (`notebook`, `review(id)`, `timeline`, `recap(id)`, `storage`) so the C tasks only write hooks.
- `query/campaignWrite.ts`: `useCampaignWrite<TVars, TRes>(fn: (vars, ctx: { latest: Campaign | undefined }) => Promise<TRes>, opts?)` returns a `useMutation` with `scope: { id: "campaign" }`. `ctx.latest` is read from the cache **when the mutation runs**. Before resolving, the mutation function applies the response to the cache (`setQueryData`) when the endpoint returns the updated entity or campaign, and otherwise invalidates `keys.campaign()`. Document the rule in a comment: *computed from the latest entry when it runs; each response applied before the next write.*
- `campaign/mutations.ts`: port every campaign write as a hook built on `useCampaignWrite`: `useMutateEntity`, `useDeleteEntity`, `useMergeEntity`, `useReviewEntity`, `useAddEntityFact`, `useSetCampaignFacts`, `useAddCampaignFact`, `useIgnoreWord`, `useUnignoreWord`, `useRejectMisheard`, `useUnrejectMisheard`, `useImportNotes`, `useWriteUp`, `useSeekFacts`. Optimistic `ignore` as before, with rollback on error.
- `<domain>/queries.ts` for each existing domain: `useCampaign()`, `useEntity(name)`, `useSuggestions()`, `useSessions()`, `useSessionRecord(id)`, `useSessionQuality(id)`, `useCloud()`, `useCloudAccount()`, `useCloudVaults()`, `useLlm()`, `useModelSettings()`, `useMics()`, `useSources()`, `useClones()`, plus mutations where ordering doesn't matter (`useStartSession`, `useOpenCampaign`, …). Empty `queries.ts` files in `notebook/`, `review/`, `timeline/`, `recap/` and `storage/` (with a comment naming the C-task).
- `query/bridge.ts`: `bridgeSocket(socket, client)`. On `campaign.updated`, invalidate `keys.campaign()` and `keys.suggestions()` with a 300 ms debounce. On `campaign.job` and `campaign.answer`, patch them into the cached `Campaign` (jobs by id, answers by id). On `cloud.updated`, `setQueryData(keys.cloud(), data)`. On `llm.updated`, patch `keys.llm()`. On `campaigns.updated`, set it. On `snapshot`, after a campaign switch (the campaign id changed), invalidate everything except live-only keys. When the live session goes from running to idle, invalidate `keys.sessions()` (a new saved session).
- `query/index.ts`: export it all.

## Tests
- `campaignWrite`: two writes fired together run one after another; the second sees the first's response in `ctx.latest` (mock fetch with a delayed first response); an error doesn't block the next write.
- `bridge`: `campaign.job` patches the cache; `campaign.updated` invalidates once for three events within 300 ms (fake timers); running → idle invalidates sessions.
- One hook test with `renderHook` + `QueryClientProvider` + `mockFetch` (`useCampaign`).
