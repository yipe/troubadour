## Build (one file per component in `src/components/`)
- `Input`, `Textarea`: 32px tall controls, `rounded-control`, `bg-sunken border-line`, focus `border-accent-strong`.
- `SearchInput`: an `Input` with a leading lucide `Search` icon and an optional `onClear`.
- `NativeSelect`: a styled `<select>`. Optional `leading` slot (the class colour dot in the players table).
- `Switch` (base-ui Switch, 32×18, on = `accent-strong`), `Checkbox` (base-ui, 16px, checked = `accent-strong`), `Slider` (base-ui, track `line`, range `accent-strong`, white thumb).
- `Field`: `label` (12px `ink-subtle`), the control, `hint` (12px `ink-subtle`), `error` (12px `danger`). It links label and control with `useId`.
- `ColorSwatchPicker`: `{ value: string | null, onChange(hex | null), label?, allowClear? }`. A trigger button shows the current swatch (or "auto" when null). A `Popover` (U3 runs in parallel, so use base-ui's Popover directly here) holds a grid: rows = `SWATCH_SHADES`, columns = `SWATCH_HUES`, each an 18px button with `aria-label` = name and `aria-pressed`. With `allowClear`, a "Use class colour" button calls `onChange(null)`. This mirrors DPRcalc's `ColorSwatchPicker` on purpose, with the same palette data; keep the behaviour the same.
- `gallery/sections/forms.tsx`: every control in every state.

## Tests (`forms.test.tsx`)
- `Field` connects the label (`getByLabelText` finds the input).
- `Switch` and `Checkbox` toggle and call `onCheckedChange`.
- `ColorSwatchPicker`: open it, click a swatch, and `onChange` gets that hex; "Use class colour" gives `null`; the selected swatch has `aria-pressed=true`.
