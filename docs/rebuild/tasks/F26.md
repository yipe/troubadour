# F26 · Settings › Content: classes and D&D terms

**Deps:** F20, F18, C1 · **Size:** M · **Owns:** see `dag.toml`

Owner request (2026-10-30): move Classes out of Players & voices into its own settings tab, "Content". The
same tab manages the D&D terms the spelling cleanup knows: see them, add your own, upload a list, remove
your own.

## Read first
- `web/app/src/pages/settings/index.tsx` (F18 shell: rail items, lazy sections that export `Component`), `web/app/src/paths.ts` (`SETTINGS_SECTIONS`), `web/app/src/pages/settings/sections/players/ClassesSection.tsx` (+ its tests in `players/index.test.tsx`).
- `backend/packages/lore/src/troubadour/lore/dnd_terms.py` (built-in SRD list + optional local list `DATA_DIR/dnd_terms.json`, cached by mtime), its callers (`cleanup.py`, the glossary/ASR prompt), `backend/AGENTS.md` (hard rules on licensed data).

## Rules (licensed data, public repo)
- Never modify or rewrite `DATA_DIR/dnd_terms.json` (the user's existing local list): show it read-only, by count and searchable, and never name where it came from.
- User terms go in a new file, `DATA_DIR/custom_terms.json` (`{"terms": [[name, type], ...]}`, written atomically). Uploads merge into it. Nothing user-supplied is ever committed; tests use tmp dirs.
- Terms are names speech-to-text mangles; keep the cleanup rule "never fix everyday speech": reject entries that are a single common dictionary word (reuse `cleanup`'s everyday-word check) with a clear message.

## Steps
1. Backend (`lore/dnd_terms.py`): `custom_path()`, `custom()`, `add_custom(names_types)`, `remove_custom(name)`; `terms()` = custom + local + built-in, de-duplicated case-insensitively (custom wins), cache invalidated on either file's mtime. Types limited to the glossary's types. Caps: name ≤ 60 chars, ≤ 5000 custom terms.
2. Router (`routers/terms.py`, registered in `app.py`): `GET /api/terms?q=&source=&offset=&limit=` → `{counts: {builtin, local, custom}, items: [{name, type, source}]}` (paged, ≤ 200); `POST /api/terms {terms: [{name, type}]}` → `{added, skipped: [{name, reason}]}`; `DELETE /api/terms/{name}` (custom only; 404 otherwise); `POST /api/terms/upload` (text body: one term per line, optional `name,type` CSV, or the `{"terms": [...]}` JSON shape; ≤ 1 MB) → same as POST. Pydantic models + `response_model`, caps on every string/list. Add the routes to `tests/test_routes.py`.
3. Web API: domain `@troubadour/api/terms` (types from `Schemas`, endpoints, `useTerms(query)`, `useAddTerms`, `useRemoveTerm`, `useUploadTerms`; invalidate `keys.terms()` — add the key).
4. Settings: `SETTINGS_SECTIONS` gains `"content"` (rail label "Content", icon `library` or `book-marked`, between Players & voices and Obsidian vault). New section `sections/content/`: a Classes card (move `ClassesSection` here unchanged, delete it from players) and a "D&D terms" card: counts per source, search, a source filter (All / Built-in / Your local list / Added by you), the list (type badge; a remove button only on yours), an add form (name + type), and "Upload a list…" (file input accepting .txt/.csv/.json) with the added/skipped result shown inline.
5. Players & voices no longer shows Classes; its tests move with it.

## Tests

- Web: Content section lists classes (moved tests pass); terms list filters and searches; add, remove and upload send the right requests and show skipped reasons; Players & voices has no Classes card.
