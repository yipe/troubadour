# B6 · API types generated from the server's OpenAPI schema

**Deps:** B5, A1 · **Size:** M · **Owns:** `server/openapi.py`, `server/routers/players.py` (pilot only), `web/packages/api/scripts/`, `web/packages/api/src/campaigns/types.ts`, `backend/tests/test_openapi.py`

- `server/app.py`, `server/deps.py` (**importing the app builds the Engine, which reads `DATA_DIR`**).
- `web/packages/api/package.json`: W1 left the `gen` script calling `node scripts/gen.ts` (a stub), and `pretypecheck` calling it.

## Goal
Types for endpoints with pydantic `response_model`s are generated from FastAPI's OpenAPI schema, so the
backend and frontend can't drift. Nothing generated is committed: it's built before every typecheck.

## Build
1. `troubadour/server/openapi.py`, run as `python -m troubadour.server.openapi <out.json>`:
   - **Before importing the app**, point the process at a throwaway world: set `TROUBADOUR_DATA` to a new
     `tempfile.mkdtemp()`, `TROUBADOUR_MODELS=0`, `TROUBADOUR_LLM_URL=http://127.0.0.1:9/v1`, and unset
     `TROUBADOUR_VAULT`. Importing `troubadour.server.app` constructs the Engine, which would otherwise read
     and write the real `~/troubador`. Comment this at the top of the file.
   - Then `json.dump(app.openapi(), out, sort_keys=True, indent=1)`. Delete the temp dir afterwards.
2. `web/packages/api/scripts/gen.ts` (replace W1's stub): run the Python module through
   `uv run --project ../../../backend` into `src/generated/openapi.json`, then `openapi-typescript` on it
   into `src/generated/schema.d.ts`. Fail with a readable message if `uv` is missing ("Run `yarn setup`
   first"). Both outputs are git-ignored (W1 added `src/generated/` to `.gitignore`).
3. `gen.ts` also writes `src/generated/index.ts`, so domain files have one import:
   `export type { components } from "./schema"` and
   `export type Schemas = import("./schema").components["schemas"]`.
   The whole `src/generated/` folder is generated; nothing in it is hand-written.
4. **Pilot** the pattern end to end on one small, stable endpoint, `GET /api/campaigns`:
   - in `routers/players.py`, add `response_model=CampaignsOut` (pydantic, the same fields as today's payload);
   - in `web/packages/api/src/campaigns/types.ts`, replace the hand-written types with
     `export type Campaigns = Schemas["CampaignsOut"]` and `export type CampaignInfo = Schemas["CampaignInfo"]`;
   - in your report, write the recipe the C-tasks follow (pydantic model → `response_model` → `Schemas["X"]`).
5. `tests/test_openapi.py`: the module runs in a subprocess with `HOME` set to a temp dir, writes valid
   JSON that contains `/api/campaigns`, and leaves no files outside its temp dir. Assert the user's real data
   dir isn't touched by checking the env it set.

## Acceptance
- `pnpm -C web/packages/api gen` writes `src/generated/{openapi.json,schema.d.ts,index.ts}`; `git status` shows none of them.
- `pnpm -C web typecheck` from a clean clone (after `yarn setup`) works with no manual step.
- `uv run pytest tests/test_openapi.py` passes; `yarn check` passes.
