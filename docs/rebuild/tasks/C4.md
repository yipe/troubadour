## Goal
While a session runs, "Tonight's notebook" fills with candidate facts, fact updates, new entries and spelling
fixes a few minutes after they're said. Nothing is written to the vault.

## `lore/notebook.py` (pure; the LLM is passed in)
`propose(llm, lines: list[Line], known: Known) -> list[dict]` where `Line = {id, t, speaker, player_id, is_gm, text}`
and `Known = {entities: [(name, type, aliases)], facts: [(about, text)]}` (facts only for entities named in the
window, at most 40).
- One `llm.json` call. System prompt: `TABLE_RULES` plus instructions to return `facts` (lasting things, each
  with `about` (a name), `text` (≤ 200 chars), `line` (the number of the line it came from, as numbered in the
  prompt), `confidence` in {gm, theory, once} defined as "the GM narrated or confirmed it" / "a player's guess" /
  "said once, unconfirmed"), `updates` (`replaces` = the number of a known fact it changes, `text`, `line`) and
  `entries` (`name`, `type` from the glossary types, `line`).
- Validate everything. `about` must name a known entity or a new entry in this answer; `line` must be in range;
  `replaces` in range; entry names must appear verbatim (case-insensitive) in the window's text and not already
  be a known name or alias; drop `fleeting` facts and ones `same_fact` as a known fact. At most 8 facts, 3
  updates and 5 entries per pass.
- Map to `NotebookItem` dicts (status `open`, `said_by` from the cited line, `t` and `line_id` from it).

`spellings(messages) -> list[dict]`: deterministic, no LLM. Group the session's applied `fixes` by
(heard → fixed text) and make one `spelling` item per pair with `count` = lines; the id is stable per pair, so
re-running updates the count instead of adding a duplicate.

## `engine/notebook.py` (extend C3's class)
- A `NotebookLoop` thread per live session. It wakes every 10 s. When at least **180 s of new speech** (sum of
  `t_end - t_start` over lines finalised since the last pass) has accumulated, it runs one pass over those lines
  plus 60 s of earlier context (at most 120 lines). One pass at a time; `updating` is true during a pass.
- It uses the **live model** (`engine.cleanup_llm`, the one spelling cleanup uses); the memory model is too slow
  for this cadence. If the LLM is down (`llm_ok` false), it skips the pass and keeps the speech counted.
- It never holds `engine.lock` while calling the LLM: copy the lines under the lock, release it, call, then
  re-check `sess is self.live` before adding items.
- `spellings()` refreshes after every pass and when the session finishes.
- Stops with the session; the final notebook is saved by C3's finish hook.
- `config.env("NOTEBOOK", "1") == "0"` turns the loop off (for stress tests).

## Tests (`test_notebook_llm.py`, `ScriptedLLM` / `FakeLLM`)
- Valid output → items with the right `line_id`, `t`, `said_by`.
- Adversarial output: an invented entry name not in the text, `line` out of range, `replaces` out of range, an unknown `about`, 50 facts, a wrong confidence value. All are dropped or clamped; nothing crashes.
- The cadence: under 180 s of speech, no call; over it, exactly one call; a second pass waits for the first.
- An abandoned session: the pass result is discarded.
- The LLM down → no call, speech still counted.
- `spellings` groups fixes and is stable across runs.
