# F32 · Refresh a session, and upgrade old sessions after a software update

**Deps:** F30 · **Size:** L · **Owns:** see `dag.toml`

Owner request (2026-10-30): a "refresh everything" button that re-runs all the processing on a saved session
(speakers, spelling, in-character, write-up, places/scenes, facts…) so data made by old versions comes out
fresh. And, for the future: after a big software update, a way to upgrade old sessions to the new
functionality.

## Design (decided by the orchestrator; keep it)
A blunt "redo everything" re-runs slow steps that didn't change and can clobber the user's work. Instead,
every derived artefact records **which version of which step made it**, and both the button and future
upgrades run the same step pipeline:

- `engine/pipeline.py` declares the steps, in dependency order, each with an integer `VERSION`, what it needs,
  and what it writes. At least: `transcribe` (Whisper re-listen; needs audio), `speakers` (re-match lines to
  voiceprints; needs audio), `spelling` (cleanup), `talk` (talk seconds), `in_character`, `writeup`
  (notes → page → facts → scenes), `review` (re-derive the review list), `recap` (only if one exists).
  Reuse the existing jobs (`improve.py` run/retranscribe/fix_spellings, `memory` write-up, C7 scenes, C8
  review, C10 recap); don't duplicate their logic. Inventory what exists first and record the mapping in the
  module docstring; a step that has no implementation yet is listed with `available=False` and skipped.
- Each saved session's `meta.json` gets `pipeline: {step: version}` written when a step completes. Sessions
  without it are version 0 for every step. `stale(session)` = steps whose recorded version < current.
- **Refresh this session** (the Improve dialog, top, primary): one background job (`campaign.job`, kind
  `"refresh"`, with `steps` so S6's `JobStatus` panel shows progress) running every available step in order.
  The dialog explains what it does and what it keeps: originals are kept (Improve's `transcript.orig.json`
  restore point is taken before the first rewriting step); the old write-up page moves to the vault's
  `.trash` before the new one is written; confirmed facts are never deleted or changed — new facts arrive as
  suggestions for review (deduped with `same_fact`); the review list is re-derived (old `review.json`
  archived next to it). Cancellable between steps; a failed step stops the job and leaves completed steps
  recorded.
- **Upgrade old sessions** (campaign level): `GET /api/sessions/upgrades` → `{sessions: [{id, n, stale:
  [step]}], current: {step: version}}`. When any session is stale, Home and the Sessions list show a quiet
  banner: "3 sessions were processed by an older Troubadour. Upgrade them" → runs the refresh pipeline per
  session, **only the stale steps**, one session at a time (queued jobs), oldest first. Resumable: a restart
  continues from the recorded versions.
- Bumping a step's `VERSION` in code is how a future update asks for an upgrade. Document that in
  `backend/AGENTS.md` (owned here for that one section) with the rule: bump only when output meaningfully
  changes.
- Never during a live session (409), never on the live session.

## Tests
- Python: version bookkeeping (old sessions = 0; steps recorded on success only); refresh runs steps in order,
  skips unavailable ones, stops on failure; confirmed facts unchanged after a refresh while new ones arrive as
  suggestions; old write-up page in `.trash`; upgrades list only stale steps; 409 while live. Scripted fake
  LLM and stubbed Whisper; no models.
- Web: the Improve dialog's Refresh button starts the job and shows its steps; the upgrade banner appears only
  with stale sessions and starts the queue.

## Acceptance
`yarn check` passes. Never run against the real server; the scratch server has no models, so check the UI
there and the pipeline in tests.
