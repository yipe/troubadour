# U0 · @yipe/tokens: colour tokens + class/rarity/swatch data, synced from DPRcalc

**Deps:** W1 · **Size:** M · **Owns:** `web/packages/tokens/`

## Read first
- `docs/rebuild/design-system.md` → *Shared with DPRcalc* (what is shared, what isn't, why).
- In the DPRcalc checkout (`$DPR_DIR`, default `~/src/dpr`, **read-only**): `packages/ui/src/theme/tokens.css`, `classColors.ts`, `postChartPalette.ts`, `AGENTS.md`.

## Goal
A framework-free package that both apps can use: the same CSS variable names and values as DPRcalc, generated
from it by a script, so the two never drift by hand.

## `scripts/sync.ts`
1. `DPR_DIR` env, else `~/src/dpr`. If it's missing, print "DPRcalc checkout not found; the committed files stay as they are" and exit 0. CI never runs sync.
2. Parse `tokens.css` into theme blocks by selector (`:root,[data-theme='dark']`, `[data-theme='light']`, `[data-theme='midnight']`). Keep only declarations whose name matches the allow-list:
   `--gray-*`, `--blue-*`, `--red-*`, `--green-*`, `--orange-*`, `--purple-*`, `--color-bg-*`, `--color-fg-*` (excluding `--color-fg-on-success-btn`), `--color-border-*`, `--color-accent-*`, `--color-success-*`, `--color-danger-*`, `--color-warning-*`, `--color-info-*`, `--color-rarity-*`, `--color-chart-*`, `--color-tooltip-*`, `--color-subtle-badge-*`, `--color-skeleton-*`, `--class-*-base`, `--color-class-*`, **except** `--class-artificer-base` and `--color-class-artificer` (not an SRD class; AGENTS.md rule 5. Users add classes like it in the app; see C1).
   Drop every comment. Drop any declaration whose value uses a `var(--x)` that isn't kept, and list those in the output so a person can extend the allow-list.
3. Write `tokens.css` with a header line: `/* Generated by scripts/sync.ts from DPRcalc <sha>. Don't edit. */`. Keep the selectors identical. Sort declarations by group in the order above, so diffs are stable.
4. Generate `classes.ts` from the `--class-*-base` declarations: `CLASS_NAMES` lowercase in DPRcalc's order (barbarian … wizard; 12 SRD classes), `CLASS_LABELS` (capitalised), `CLASS_BASE_COLORS`. `classColorVar(c) = \`var(--color-class-${c})\``.
5. Generate `palette.ts` from `postChartPalette.ts` by importing it (with `node --experimental-strip-types`, or a regex if the import pulls in Chakra). Copy the data only, no logic.
6. Run prettier on the outputs.

## Tests (`src/tokens.test.ts`, read the committed files)
- Every theme block defines every key in `REQUIRED` (the list in `design-system.md`'s Tailwind table plus the class and rarity vars).
- `CLASS_BASE_COLORS[c]` equals the `--class-<c>-base` value in the dark block, for every class.
- `tokens.css` contains no `/*` comment other than the header, and no `artificer`.
- `CLASS_NAMES.length === 12`.
- `SWATCH_PALETTE` has `SWATCH_HUES.length` hues, each with light/medium/dark hex values.

## Acceptance
- `pnpm -C web/packages/tokens sync` with the local DPRcalc checkout produces the files, and a second run produces no diff.
- `DPR_DIR=/nope pnpm -C web/packages/tokens sync` exits 0 and changes nothing.
- `pnpm -C web/packages/tokens test` and `typecheck` pass.
- `grep -ci "phb\|ddb\|beyond" web/packages/tokens/tokens.css web/packages/tokens/src/*.ts` prints 0 (public repo: values only).
