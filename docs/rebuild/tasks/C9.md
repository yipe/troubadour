## Backend (`lore/timeline.py`, `routers/timeline.py`, `routers/campaign.py`)
1. `GET /api/campaign/timeline` → `{sessions: TimelineSession[]}`, newest first:
   `{id, n, date, title, places: string[], talk: Record<string, number>, new_entities: {name, type}[], facts_accepted: number}`.
   - `places`: the scenes' places in order, consecutive duplicates removed; with no scenes, the Place entries mentioned in the transcript ordered by first mention (at most 3).
   - `new_entities`: confirmed entries whose first mention across all sessions is in this session.
   - `facts_accepted`: confirmed facts whose `source.session_id` is this session.
   - Mention scanning reads every transcript, so cache per session by `(id, transcript mtime, vault generation)`. Give the vault a counter that bumps on `changed()`; if it has none, add it in `timeline.py` by hooking `memory.changed()`.
2. `GET /api/campaign/entities/{name}` adds `appearances: [{session_id, n, count}]`, one per saved session (oldest first, zero counts included, so the chart has all columns).
3. Must hold up at 50+ sessions: one pass per uncached session; test the cache.

## Web
`@troubadour/api/timeline`: types, `timeline()`, `useTimeline()`. `@troubadour/api/campaign`: `Entity.appearances?` (optional: only the detail endpoint returns it), `useEntity(name)` returns it.

## Contract rule
Every endpoint you add or change declares a pydantic `response_model` (payload shapes as classes in the router, or in `server/models.py` when two routers share one). In `@troubadour/api`, its types are `Schemas["<Model>"]` from `../generated` (the B6 recipe), not hand copies. WebSocket payloads reuse the same models. Run `pnpm -C web/packages/api gen` after changing a model.

## Tests (`test_timeline.py`)
Places from scenes vs fallback; `new_entities` only on first mention; `facts_accepted` counts by source; appearances with zeros; the cache isn't recomputed on a second call and is after a vault change.
