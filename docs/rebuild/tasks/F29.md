# F29 · Codex list: a mention bitmap under each entry

**Deps:** F14, F15, C9 · **Size:** M · **Owns:** see `dag.toml`

Owner request (2026-10-30): under each entry in the Codex list, a thin row of dots, one per session (oldest
left), lit where the entry was mentioned, shaded by how often. Horizontal space holds many sessions.

## Read first
- `backend/packages/lore/src/troubadour/lore/timeline.py` (per-session transcript scan, cached by mtime + names fingerprint; `appearances` for one entry), `backend/packages/server/src/troubadour/server/routers/timeline.py` (`GET /api/campaign/entities/{name}` appearances, `session_context()`).
- `web/packages/api/src/timeline/` and `campaign/` (`useEntity` appearances), `web/app/src/pages/codex/EntryRail.tsx`, `AppearancesChart.tsx`.

## Steps
1. Backend: `GET /api/campaign/appearances` → `{sessions: [{id, n}], counts: {<entry name>: [int, ...]}}` (one int per session, same order as `sessions`, oldest first), from the same cached scan the timeline uses (one pass for all entries; never rescans per entry). `response_model` with caps; add to `tests/test_routes.py`.
2. Web API: `useAppearances()` in `@troubadour/api/timeline` (invalidated by `campaign.updated` via its key under `["campaign", …]`, like the entity detail).
3. `EntryRail`: under each entry's name line, a `MentionBits` row: one 3×3 px square per session with 1 px gaps, `bg-line` when 0, `bg-accent` with opacity stepped by count (1, 2–3, 4+); an item entry uses `legendary`. Wraps to a second line only if needed; `aria-label` "Mentioned in 7 of 12 sessions"; `title` per dot "S5: 3 mentions". Rendered only when data loaded; zero layout shift.
4. Keep it page-local (`pages/codex/MentionBits.tsx`) until a second page wants it.

## Tests
- Python: counts for several entries in one call; aliases counted; cache reused (scan called once for two requests).
- Web: dots per session with the right lit/unlit pattern and label; renders nothing while loading.
