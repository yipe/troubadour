## Goal
`Entity.facts` and `Entity.suggested_facts` hold `Fact` objects end to end. The vault still reads and writes the
same notes, now in the new bullet format. **Old notes load and are not rewritten until Troubadour changes them.**

## Steps
1. `Entity.facts: list[Fact]`, `suggested_facts: list[Fact]`; campaign facts too. Parse with `parse_bullets` and render with `render_bullets` (session numbers and page names from the vault's `Sessions/` pages plus the engine's sessions; pass a resolver into `Vault`).
2. `said_by.player_id` is resolved at the API boundary: match `said_by` against seated players' names and characters, case-insensitively. Return `said_by: {name, player_id}` or null.
3. API `Fact` JSON: `{id, text, about, said_by, source: {session_id, t, label} | null, confidence, history: [{text, said_by, source, confidence}]}`; `FactSuggestion` = `Fact` + `kind: "new"` + `replaces: null` (C7 sets real values).
4. Writes (keep the URLs; change the bodies to address facts by `id`):
   - review accept/reject a suggested fact by `fact_id`; accepting a suggestion with `replaces` (an existing fact id) moves the old fact into the new fact's `history` (newest first), keeping its trailer.
   - add a fact `{text, confidence?, source?, said_by?}`; edit a fact `{fact_id, text?, confidence?}` (an edit of the text pushes the old version into history only when the client says `as_update: true`; a plain edit fixes a typo in place).
   - delete a fact by id.
   - campaign facts: the same shapes with `about: null`.
   Every write is a patch on the latest note (the "patches, not replacements" invariant), calls `memory.changed()`, and returns the updated entity.
5. Update every consumer: `memory.py` (import, write-up, look for facts: build `Fact`s with `source` from the page name, `confidence="once"`; C7 enriches the write-up), `ask.py` (index `fact.text` plus trailer info as passage text), `talk.py`, `cleanup.py`, `same_fact` and `add_unique` (compare `.text`).
6. `spike/seed/vault.py`: facts in the new format with sources, speakers and confidences (data.js has them); one fact with history ("Orsa Vell owes Pip 20 gold" → "paid Pip back"); a few old-format bullets to prove both load.
7. `@troubadour/api/campaign`: `Fact`, `FactSuggestion`, `FactSource`; update `Entity` and `Campaign`; update the fact mutations in `mutations.ts` to the new bodies (`useAddEntityFact`, `useEditFact`, `useDeleteFact`, `useReviewFact`, campaign-fact equivalents).

## Contract rule
Every endpoint you add or change declares a pydantic `response_model` (payload shapes as classes in the router, or in `server/models.py` when two routers share one). In `@troubadour/api`, its types are `Schemas["<Model>"]` from `../generated` (the B6 recipe), not hand copies. WebSocket payloads reuse the same models. Run `pnpm -C web/packages/api gen` after changing a model.

## Tests (`test_facts_vault.py`, plus minimal fixes to existing tests)
- An old-format note loads; GET doesn't change the file on disk (compare bytes and mtime).
- Add a fact → the note has the canonical bullet; accept an update suggestion → history nested correctly; reject → gone; a typo edit → no history; `as_update` → history.
- A note with unparseable frontmatter stays read-only (existing rule).
- Ask still finds a fact's text.
- `said_by.player_id` resolves by character name.
