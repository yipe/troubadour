## Backend (`lore/recap.py`, `routers/recap.py`)
- `POST /api/sessions/{id}/recap {voice: "narrator"|"chronicle"|"bullets", length_s: 15..120, include: {happened: bool, quote: bool, moments: bool, questions: bool}}` → a job (`kind: "recap"`, title = session id). 409 if one is already running for that session.
- Inputs: the session page's title and wrap-up, **confirmed** facts whose source is this session (never suggested ones), with their confidence, and up to 30 quote candidates: player lines of 6–25 words, spread across the session, numbered.
- One `llm.json` call (memory model). Schema: `title` (≤ 80), `body` (≤ `length_s × 2.6` words; bullets voice: 3–6 lines), `quote` (a candidate number or -1), `moments` (`[{player_id, text ≤ 70 chars}]`, ids from a given list of present players), `questions` (≤ 3, each ≤ 100 chars). The prompt says: theories must be worded as theories ("Velis is sure the diamond…"), only use the facts and the page, second person plural for the narrator voice.
- Validate: an unknown `player_id` → dropped; quote out of range → none; over-long body → cut at a sentence boundary under the cap.
- Store `sessions/<id>/recap.json`: `{title, body, quote: {text, speaker, player_id, t} | null, moments, questions, options, built_at}`. `GET /api/sessions/{id}/recap` → it, or null.

## Web (`@troubadour/api/recap`)
Types, endpoints, `useRecap(id)`, `useBuildRecap(id)`. (`CampaignJob.kind` already includes `"recap"` from A1.)

## Contract rule
Every endpoint you add or change declares a pydantic `response_model` (payload shapes as classes in the router, or in `server/models.py` when two routers share one). In `@troubadour/api`, its types are `Schemas["<Model>"]` from `../generated` (the B6 recipe), not hand copies. WebSocket payloads reuse the same models. Run `pnpm -C web/packages/api gen` after changing a model.

## Tests (`test_recap.py`, `FakeLLM`)
Unreviewed (suggested) facts never appear in the prompt; options change the prompt; validation of player ids, quote index and body length; the job stores and GET returns it; a second POST while running → 409.
