# F31 · Microphone picker: live availability, refresh, and visible test errors

**Deps:** S7, F19 · **Size:** S · **Owns:** see `dag.toml`

Owner request (2026-10-30): on the ready check, Test on a mic that isn't plugged in did nothing: no error.
The device dropdown should show whether each mic is available, live, with a refresh button next to it.

## Read first
- `web/app/src/components/mic/MicCard.tsx` (`start.mutate(...)` has no error handling; the server answers 400 "Couldn't open the microphone: …"), `LevelMeter48.tsx`, `MicCard.test.tsx`.
- `@troubadour/api/audio` (`useMics`, `useStartMicTest`), `backend/packages/sound/src/troubadour/sound/mics.py`, `backend/packages/server/src/troubadour/server/routers/audio.py` (`GET /api/mics`), `backend/packages/engine/src/troubadour/engine/core.py` (`mic_test`).

## Steps
1. Errors: a failed start (or a `mic.test` event reporting an error) shows inline under the Test button in `text-danger`, with the server's message ("Couldn't open Yeti 2: it isn't connected."). Clear it on the next attempt or device change. Never silent.
2. Availability: the list returns what's plugged in now. A mic the user picked before (the remembered/selected device) that is no longer in the list stays in the dropdown as "Yeti 2 (not connected)" so the choice isn't silently swapped; Test is disabled for it with the reason as a tooltip/hint. If the backend can't tell a remembered mic from a present one, add `connected: bool` to the mic list response (sounddevice query at request time; `response_model` updated; types regenerated).
3. Live: `useMics` refetches every 2 s while the card is mounted and no session or mic test is running (the ready page already polls; move the polling here so settings and wizard get it too, and drop the duplicate in `pages/ready` only if F24 has merged — otherwise leave it and report).
4. Refresh: an icon button (`RefreshCw`, `aria-label="Refresh microphones"`) beside the select refetches immediately and spins while fetching.
5. Backend: `mic_test` with a device that isn't present fails fast with a clear message (no silent fallback to the default mic).

## Tests
- Web: a 400 from `/api/mic/test` shows its message; an unplugged remembered mic shows "(not connected)" and disables Test; refresh refetches `/api/mics`; polling stops while a test runs.
- Python: `mic_test` on a missing device raises a ValueError naming it (sounddevice faked).

## Rules
Never start a real mic test or session; tests fake the mic. Never play audio.

## Acceptance
`yarn check` passes.
