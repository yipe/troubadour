# C14 · Ask: answer stats (time, transcripts, notes)

**Deps:** C6, B6 · **Size:** S

## Build
- `CampaignAnswer` gains `stats: {seconds, transcripts, notes} | null` (seconds the answer took; transcripts and notes in the searched corpus) and `t: number | null`.
- `POST /api/campaign/ask` accepts optional `t` (0..86400), the live session time when asked, echoed back.
- The "searching" state carries `stats` with `seconds: 0` as soon as the corpus is counted, so the UI can say "Searching 13 transcripts and 214 notes…".
- Ask's note corpus skips the vault's `_Overview/` folder (C13 generates it; it would duplicate everything).

## Web (`@troubadour/api/ask`)
Types; `ask(question, t?)`.

## Contract rule
Every endpoint you add or change declares a pydantic `response_model` (payload shapes as classes in the router, or in `server/models.py` when two routers share one). In `@troubadour/api`, its types are `Schemas["<Model>"]` from `../generated` (the B6 recipe), not hand copies. WebSocket payloads reuse the same models. Run `pnpm -C web/packages/api gen` after changing a model.

## Tests (`test_ask_stats.py`)
Stats counts on a fixture vault and sessions; `t` echoed; `_Overview/` notes aren't searched.
