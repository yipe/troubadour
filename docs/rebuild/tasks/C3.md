## Shapes (copy into `@troubadour/api/notebook/types.ts`)
```ts
type NotebookStatus = "open" | "kept" | "dismissed"
interface NotebookItem {
  id: string
  kind: "fact" | "update" | "entry" | "spelling"
  text: string                 // fact text; entry name; "Isolde → Ysolde"
  old: string | null           // update: the fact it replaces
  about: string | null         // entity name the fact is about
  entry_type: EntityType | null
  said_by: { name: string; player_id: string | null } | null
  t: number | null             // session seconds of the source line
  line_id: string | null
  confidence: "gm" | "theory" | "once" | null
  count: number | null         // spelling: lines fixed tonight
  status: NotebookStatus
}
interface Pin { id: string; t: number; text: string; created_at: number }
interface Notebook { session_id: string | null; items: NotebookItem[]; pins: Pin[]; updating: boolean }
```

## Backend
1. `engine/notebook.py`: a `Notebook` class per live session (held on `LiveSession`) with `items`, `pins`, `updating`, its own small lock, and methods `add_items(items)` (C4 calls it), `set_status(item_id, status)`, `add_pin(t, text)`, `to_json()`, `save(path)` and `load(path)`. Every change emits `notebook.updated` with `to_json()`.
2. Session isolation: every mutation checks the session is still the live one (the `sess is self.live` rule), so an abandoned session never emits or saves.
3. On finish, write `sessions/<id>/notebook.json` (`write_atomic`).
4. Routes (`routers/notebook.py`):
   - `GET /api/session/notebook`: the live notebook, or `{session_id: null, items: [], pins: [], updating: false}` when idle.
   - `POST /api/session/pins {t: 0..86400, text: 1..500}` → `Pin` (400 when idle).
   - `POST /api/session/notebook/{item_id} {status}` → the item (404 for an unknown id).
   - `GET /api/sessions/{id}/notebook` → the saved notebook, or an empty one.
5. The `snapshot` event doesn't carry the notebook. The client fetches `GET /api/session/notebook` on connect and after a snapshot.
6. `spike/seed/notebook.py`: a saved notebook for S12 with two kept facts, one dismissed, and one pin.

## Contract rule
Every endpoint you add or change declares a pydantic `response_model` (payload shapes as classes in the router, or in `server/models.py` when two routers share one). In `@troubadour/api`, its types are `Schemas["<Model>"]` from `../generated` (the B6 recipe), not hand copies. WebSocket payloads reuse the same models. Run `pnpm -C web/packages/api gen` after changing a model.

## Tests (`backend/tests/test_notebook_api.py`)
A pin while running → returned and emitted; a pin while idle → 400; set status → emitted and persisted on finish; an abandoned session emits nothing after it's abandoned; the saved notebook is readable; text length caps.
